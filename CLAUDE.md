# agent-engineer-system

WhatsApp-controlled autonomous coding agent. Full architecture and setup: `README.md`.

## Writing style — this applies everywhere: code comments, commit messages, WhatsApp copy, docs

Nothing in this project should read like it was generated by an AI. Concretely:

- **Comments**: only write one when the *why* isn't obvious from the code itself (a workaround, a non-obvious constraint, a gotcha discovered the hard way). Never restate what the line already says. No comment blocks, no "Step 1 / Step 2" narration.
- **WhatsApp-facing text** (`router/handler.ts`, `agent/loop.ts`, `agent/systemPrompt.ts`'s task-summary instructions, gateway error replies): casual Indonesian, like texting someone, not a formal status report. No emoji, no "I have successfully...", no restating the obvious. Don't open with or lean on "gampang"/"simpel"/"gampang kok" to frame something as easy — it reads as trivializing real work (planning, coding, testing), describe it plainly instead. See the existing strings in `handler.ts` for the target tone.
- **Commit messages the agent writes** (via the system prompt in `agent/systemPrompt.ts`): plain and specific about what changed and why, not a template ("This commit adds...", bullet-point changelogs for a one-line fix).
- **Docs** (README, this file): direct, no filler, no corporate hedging.

When editing existing files, match this tone rather than the generic default — if you spot leftover stiff/robotic phrasing while you're in a file for another reason, fix it too.
